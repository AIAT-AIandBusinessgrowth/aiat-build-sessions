## How to use a unit

Every unit starts with a small table:

| Row | What it tells you |
|---|---|
| **Prerequisites** | Units to do first. "None" means you can start here. |
| **Time** | How long doing the unit takes, not only reading it. |
| **Outcome** | What you can do afterwards. |
| **Last verified** | The date someone last checked the commands, links and numbers. Tools change. If your screen looks different, the vendor's current help page wins. |

Then come the same sections every time:

- **Why this matters:** the problem the unit solves.
- **Do it:** numbered steps with times. Text in grey boxes is a prompt or command to copy.
- **Done when:** checkboxes. The unit is finished when every box is ticked, not when you have read it. Copy the list into your notes and tick it there.
- **Data note:** how rule one applies to this unit. Read it every time, even when it sounds familiar.
- **Next:** the unit that follows.

Boxes that start with "As of" describe one tool's current commands. They carry a source link and a check date.

## When you are stuck

1. **Ask your agent.** Open this repository with your agent. [AGENTS.md](AGENTS.md) makes it answer from the material and name the file it used. Paste the error text, not a screenshot that might show real data.
2. **Check the guides.** Accounts, plans, data agreements, hosting, deploy, costs and keys are in the [Do it yourself guides](diy/01-accounts-and-2fa.md). Prices and limits are in the [tool matrix](diy/tool-matrix-2026-09.md).
3. **Start fresh.** After two failed corrections, open a new chat with a better first prompt. See [Five failure patterns](tracks/05-verify-and-loop/02-five-failure-patterns.md).
4. **Look up a word.** The [glossary](reference/glossary.md) explains terms in plain English.
5. **Ask the people next to you**, if you work in a Build Session.

Nobody provides setup support: not the authors, not the publisher, not a session host. The vendor's help pages and your own agent are the first stop.
