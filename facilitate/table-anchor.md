# Table anchor

A table anchor helps a group of 4 to 5 people get unstuck during an exercise. Try the activity beforehand, then help others find their next step while they keep the keyboard. You do not need to give a talk or know every answer.

It is a task for this session. Check the relevant [setup](../ready-to-build.md) and use the checklist below to prepare.

**No experienced anchors?** Run the session with the host plus pairs: people work in twos, and the host walks around and does the anchor job for the whole room.

## What an anchor does

- Makes sure everyone at the table has a task in the first five minutes.
- Asks one useful question and waits. Start with "What did you expect?" Then, if needed, ask what happened or how it was checked.
- Points to the unit or guide that covers the problem, instead of explaining it from memory.
- Watches for real data on screens and says so kindly.
- After two failed corrections, helps the learner save the current attempt and a short note about the failure before starting a fresh chat.
- Reminds the table to save a second copy by export or push, open it and check the latest change.
- Notes questions the material did not answer, and gives them to the host.

## What an anchor does not do

- Take over the keyboard. The person who builds types.
- Log in with their own account for someone else, or share a login.
- Install software on someone else's laptop.
- Give a long explanation while someone is trying to work. Start with a small hint or open the relevant lesson together.
- Rate or rank people.

## Checklist before the session

- [ ] I worked through [ready-to-build.md](../ready-to-build.md) myself, for at least one lane.
- [ ] I did today's unit once, and the starter prompt worked for me.
- [ ] I know [rule one](../tracks/00-orientation/01-rule-one-no-real-data.md) and the five steps in [If something went wrong](../tracks/02-data-first/04-if-something-went-wrong.md).
- [ ] I can ask "how did you check it?" and help someone [try the result themselves](../tracks/05-verify-and-loop/01-verification-ladder.md).
- [ ] I know the fallbacks for when tools fail: [run-a-build-session.md](run-a-build-session.md#when-tools-fail).
- [ ] I know where the [Do it yourself guides](../diy/01-accounts-and-2fa.md) and the [tool matrix](../diy/tool-matrix-2026-09.md) are, so I can point to them.
- [ ] My own screen shows only fake data. Mail, chat and notifications are closed.

## Useful questions at the table

- "What is the smallest version of this you could see working today?"
- "Where would you look to check that it really works?"
- "Is there anything real in that file?"
- "What would tell you this change works?"
- "Which unit covers this? Let us open it together."
