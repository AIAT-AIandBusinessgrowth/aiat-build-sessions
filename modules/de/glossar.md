## Grundlagen: Code, Hosting & Sicherheit

| Begriff | Klartext | Mehr dazu |
|---|---|---|
| **2FA (Zwei-Faktor-Authentifizierung)** | Zweiter Sicherheitsschritt beim Login neben dem Passwort, typisch per Authenticator-App (TOTP); erschwert den Missbrauch eines gestohlenen Passworts, verhindert aber nicht jeden Angriff. | [Accounts and 2FA (EN)](../../diy/01-accounts-and-2fa.md) |
| **Blast Radius** | Wirkungsbereich eines kompromittierten Tokens oder Credentials: was ein Angreifer damit maximal tun kann. | [Modul 7](./07-agenten-grundlagen.md) |
| **Branch** | Parallele Arbeits-Linie im Repo: Änderungen entwickeln, ohne den Hauptstand (`main`) zu stören; wird später per merge zusammengeführt. | [Parallel agents (EN)](../../tracks/08-advanced/03-parallel-agents.md) |
| **Commit** | Gespeicherter Änderungs-Schnappschuss mit kurzer Beschreibung, die einzelnen Bausteine der Git-Historie. | [Keep your work safe (EN)](../../tracks/06-keep-and-ship/01-keep-your-work-safe.md) |
| **Container / Docker** | Isoliertes Paket, das eine App mit allen Abhängigkeiten enthält; mehrere Container können auf einem Rechner laufen. Welche Dateien und Netzwerke sie erreichen, hängt von der Konfiguration ab. | — |
| **ed25519** | Moderner, kompakter Schlüsseltyp für SSH; wird im Setup-Guide für neue SSH-Keys verwendet. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **Firewall** | Filter vor dem Server, der Netzwerkzugriffe nach festen Regeln erlaubt oder blockiert, z.B. nur die Ports 443 und 22. | — |
| **Fork (Repo)** | Eigene Abspaltung (Kopie) eines Repos als Startpunkt: Man arbeitet im Fork mit vollen Schreibrechten und schlägt Änderungen per Pull Request bzw. Merge Request am Original vor. Nicht zu verwechseln mit dem Fork-Subagent (s. Abschnitt „Mit Agenten arbeiten"). | — |
| **git** | Werkzeug, das als Commits gespeicherte Änderungen verwaltet. So lassen sich frühere Stände vergleichen und wiederherstellen. Ungespeicherte Änderungen schützt es nicht automatisch. | [Keep your work safe (EN)](../../tracks/06-keep-and-ship/01-keep-your-work-safe.md) |
| **GitHub** | Hosting-Plattform für git-Repos (Issues, CI, Code-Reviews); Änderungsanträge heißen dort Pull Requests, das CLI heißt `gh`. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **GitLab** | Hosting-Plattform für git-Repos (Issues, CI, Code-Reviews), als GitLab.com oder selbst betriebene Instanz; Änderungsanträge heißen dort Merge Requests, das CLI heißt `glab`. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **Healthcheck** | Automatische Prüfung eines Dienstes, etwa ob er auf Anfragen antwortet. Ein erfolgreicher Check sagt nur etwas über die geprüfte Funktion. | [PoC to production checklist (EN)](../../tracks/08-advanced/06-poc-to-production-checklist.md) |
| **HTTPS / TLS** | Transport-Verschlüsselung zwischen Browser und Server (TLS), erkennbar am „s" in `https`; Git kann Repos ebenfalls über HTTPS klonen und pushen. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **IaC (Infrastructure as Code)** | Infrastruktur (Server, Firewall, Netzwerk) als versionierte Konfigurationsdateien statt per Hand geklickt: wiederholbar, nachvollziehbar, auditierbar. | — |
| **IP-Adresse** | Eindeutige Netzwerk-Adresse eines Rechners oder Servers, wie eine Postanschrift, an die Daten zugestellt werden; kann ein indirektes Personendatum sein. | [Rule one: no real data (EN)](../../tracks/00-orientation/01-rule-one-no-real-data.md) |
| **MR (Merge Request)** | GitLab-Begriff für einen Änderungsantrag: Man pusht auf einem eigenen Branch und beantragt, diesen in `main` einzumergen. GitLab-Pendant zum Pull Request. | [Modul 7](./07-agenten-grundlagen.md) |
| **MVP (Minimum Viable Product)** | Kleinste auslieferbare Version mit echtem Nutzen, gerade genug, um früh mit echten Nutzer:innen zu lernen (vgl. PoC). | [Prototype to product (EN)](../../tracks/06-keep-and-ship/02-prototype-to-product.md) |
| **OAuth / scoped Token** | Kurzlebiger, auf bestimmte Rechte beschränkter Token, der einem konkreten User zugeordnet und zentral widerrufbar ist. | [Modul 7](./07-agenten-grundlagen.md) |
| **pipeline** | Kette automatischer Schritte, die nach einem Git-Push läuft, z.B. Tests, Build und Deploy. | — |
| **PoC (Proof of Concept)** | Schneller Machbarkeitsnachweis, ob eine Idee technisch funktioniert; noch kein fertiges Produkt (vgl. MVP). | [PoC to production checklist (EN)](../../tracks/08-advanced/06-poc-to-production-checklist.md) |
| **PR (Pull Request)** | GitHub-Begriff für einen Änderungsantrag: Änderungen auf einem eigenen Branch werden zur Übernahme in `main` vorgeschlagen und dort reviewt. GitHub-Pendant zum Merge Request. | [Modul 7](./07-agenten-grundlagen.md) |
| **push / merge / pull** | push = lokale Commits zum Server hochladen; merge = einen Branch in einen anderen zusammenführen (meist über PR bzw. MR); pull = den aktuellen Stand vom Server holen. | [Keep your work safe (EN)](../../tracks/06-keep-and-ship/01-keep-your-work-safe.md) |
| **Repo (Repository)** | Versioniertes Projektverzeichnis: Ordner mit allen Projektdateien plus kompletter Historie; die lokale Arbeitskopie holst du dir mit `git clone`. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **Rollback** | Zurück auf eine frühere, funktionierende Version, etwa indem man einen Commit rückgängig macht und neu ausliefert. | [Agents in operation (EN)](../../tracks/08-advanced/04-agents-in-operation.md) |
| **Spend Cap (Kostendeckel)** | Selbst gesetzte Obergrenze für die Kosten eines Dienstes pro Monat; verhindert unerwartete Rechnungen bei Lastspitzen. | [Costs, limits and spend caps (EN)](../../diy/06-costs-limits-spend-caps.md) |
| **SSH (Secure Shell)** | Verschlüsselter Fernzugriff samt Authentifizierung per Schlüsselpaar, z.B. `git push` ohne Passwort. Wichtig: SSH authentifiziert nur den Git-Transport (`clone`/`push`), nicht die API; dafür brauchen `gh` und `glab` eine eigene Anmeldung. | [Code hosting (EN)](../../diy/04-code-hosting-and-backup.md) |
| **Supabase** | Open-Source-Backend-Plattform auf Basis von PostgreSQL mit Datenbank, Auth, Storage und Realtime. | [Deploy and share (EN)](../../diy/05-deploy-and-share.md) |
| **Token-Scope** | Berechtigungspaket eines Tokens, bei GitLab z.B. `read_api` (nur lesen), bei GitHub ein fine-grained Token mit Rechten auf genau ein Repo; nie mehr Rechte als nötig. | [Modul 7](./07-agenten-grundlagen.md) |

## Mit Agenten arbeiten

| Begriff | Klartext | Mehr dazu |
|---|---|---|
| **Ablation** | Methode, um zu prüfen, ob eine Instruktion noch gebraucht wird: komplett löschen, beobachten was passiert, dann Zeile für Zeile zurückholen und die Wirkung jeder einzelnen messen; dieselbe Grundidee wie ein Eval, nur mit Löschen statt Testen. | [Modul 10](./10-kontext-engineering.md) |
| **Adoption-Leiter (0–4)** | Fünf-Stufen-Modell fürs Arbeiten mit Agenten (Gated → Assisted → Parallel → Supervised Autonomy → AI-native), gemessen an der Größenordnung paralleler Agents. Kernaussage: Der Engpass je Stufe ist Vertrauen in Verifikation, nicht das Tool. Nicht verwechseln mit der Verification-Leiter (Eskalationsstufen der Prüf-Härte). | [Modul 8](./08-agenten-skalierung.md) |
| **Agent / Coding-Agent** | KI-Werkzeug, das eigenständig Dateien liest, Code ändert und Befehle ausführt; kein Chatbot, sondern ein iterativer Loop. | [Modul 7](./07-agenten-grundlagen.md) · [The map (EN)](../../tracks/04-the-map/01-model-context-agent.md) |
| **Agent Teams** | Automatisierte Koordination mehrerer Agenten-Sessions mit gemeinsamer Aufgabenliste (shared tasks), Messaging untereinander und einem koordinierenden Team Lead; hebt die manuelle Worktree-Parallelität auf orchestrierte Zusammenarbeit. Experimentell, per Default aus. | [Modul 8](./08-agenten-skalierung.md) |
| **Agent View (`claude agents`)** | Ein Bildschirm zum Dispatchen und Überwachen von Hintergrund-Sessions (Research Preview); jede dispatchte Session bekommt automatisch einen eigenen Worktree. | [Modul 8](./08-agenten-skalierung.md) |
| **Agent-Harness** | Das Produkt-Gerüst um ein Modell herum (System-Prompt, Tool-Set, Permissions), das bestimmt, wie viel von der eigentlichen Modell-Fähigkeit tatsächlich nutzbar wird; Claude Code selbst entstand aus der Idee, dieses Gerüst auf ein Minimum zu reduzieren (Terminal-Zugriff statt IDE-Käfig). | [Modul 10](./10-kontext-engineering.md) |
| **Akzeptanzkriterien** | Messbare, prüfbare Bedingungen, die ein Auftrag oder Issue erfüllen muss, damit „fertig" gilt (z.B. „`npm test` läuft grün"); Gegenteil von vagen Wünschen wie „schön aufbereiten". | [Modul 7](./07-agenten-grundlagen.md) |
| **Anonymisierung** | Echte Werte werden unumkehrbar entfremdet, sodass keine Person mehr herausgelöst werden kann; gilt erst als gelungen, wenn Singling out, Linkability und Inference alle drei verneint sind. Das Anonymisieren selbst ist bereits eine Verarbeitung und braucht eine Rechtsgrundlage. | [Modul 11](./11-kundendaten-testdaten.md) |
| **Auto Mode** | Claude-Code-Permission-Modus (`claude --permission-mode auto`): Ein server-seitiges Classifier-Modell prüft Befehle vorab und blockt nur Riskantes, sichere Befehle laufen ohne Rückfrage durch. Auf Pro, Max und Team startet Claude Code ab v2.1.228 (macOS/Linux/WSL) bzw. v2.1.233 (Windows nativ) im Auto Mode; der frühere Modus `default` heißt jetzt Manual. (Stand 2026-09-13, Quelle: https://code.claude.com/docs/en/permission-modes) | [Modul 8](./08-agenten-skalierung.md) |
| **Autonomy-Slider** | Konzept für das stufenweise Erhöhen oder Verringern der Selbstständigkeit eines Agenten, von „bestätige jeden Schritt" bis zum vollautomatischen Headless-Lauf; die richtige Stufe hängt vom Risiko der Aufgabe ab und wird pro Task neu gewählt. | [Modul 10](./10-kontext-engineering.md) |
| **AVV (Auftragsverarbeitungsvertrag)** | Vertrag nach Art. 28 DSGVO zwischen Auftraggeber und Dienstleister, der regelt, was der Dienstleister mit den Daten tun darf; muss **vor** der ersten Dateiübergabe stehen. Wer über die Weisung hinausgeht, wird nach Art. 28 Abs. 10 selbst Verantwortlicher und haftet voll. | [Modul 11](./11-kundendaten-testdaten.md) |
| **/batch** | Skill, der eine große Änderung in 5–30 worktree-isolierte Subagents aufteilt, die je einen eigenen Pull Request öffnen; paketierte Nutzung von Subagents plus Worktrees, kein eigener Koordinationsstil. | [Modul 8](./08-agenten-skalierung.md) |
| **Besondere Kategorien (Art. 9 DSGVO)** | Besonders geschützte Datenarten: Gesundheit, Religion, Gewerkschaftszugehörigkeit, ethnische Herkunft, politische Meinung, Sexualleben, biometrische und genetische Daten. Tauchen sie in einer Kundendatei auf, wird zurückgefragt, bevor die Datei überhaupt geöffnet wird. | [Modul 11](./11-kundendaten-testdaten.md) |
| **Builder** | Rollen-Archetyp: macht aus einem Prototyp ein production-grade Produkt bzw. tragfähige Infrastruktur; denkt an Security, Edge-Cases und Betrieb, also alles, was der Prototyper bewusst ignoriert. | [Modul 9](./09-rollen-archetypen.md) |
| **Checkpoint / `/rewind`** | Jeder Prompt ist ein Checkpoint (lokales Undo für Claudes eigene Änderungen, 30-Tage-Cleanup); `/rewind` oder doppeltes `Esc` öffnet das Menü zum Zurückrollen. Kein Ersatz für Git. | [Modul 7](./07-agenten-grundlagen.md) |
| **Classifier (server-seitig)** | Das Modell hinter Auto Mode, das Befehle vorab bewertet und risikoreiche Aktionen (Scope-Escalation, destruktive `git`-Befehle, IaC-Destroy) blockiert, unabhängig von der `/model`-Wahl. | [Modul 8](./08-agenten-skalierung.md) |
| **CLAUDE.md** | Zentrale Projekt-Instruktionsdatei, die ein Agent bei jedem Turn mitliest. Pruning-Faustregel: „Würde Entfernen dieser Zeile Claude Fehler machen lassen? Wenn nein, raus." Eine überfüllte Datei lässt den Agenten Regeln ignorieren. | [Modul 10](./10-kontext-engineering.md) |
| **CLI** | Command-Line Interface: Terminalwerkzeug, in dem der Agent läuft und Befehle tippt (`claude`, `codex`, `gh`, `glab`). | [Modul 7](./07-agenten-grundlagen.md) |
| **Cloud-Routines (`/schedule`)** | Session-unabhängige, dauerhafte Cron-Automatisierung: Agenten-Tasks laufen auf Zeitplan in der Cloud, auch wenn der eigene Rechner aus ist. | [Modul 8](./08-agenten-skalierung.md) |
| **Codex CLI** | OpenAI-Coding-Agent für das Terminal, ähnlich Claude Code, aber auf OpenAI-Modelle ausgerichtet; nützlich als Referenz-Werkzeug und Alternative im Vergleich. | [Modul 7](./07-agenten-grundlagen.md) |
| **Compaction / `/compact`** | Verdichten des Gesprächsverlaufs, wenn das Context-Window voll wird; was dabei erhalten bleiben muss, gehört in die `CLAUDE.md`. | [Modul 7](./07-agenten-grundlagen.md) · [Modul 10](./10-kontext-engineering.md) |
| **Conductor** | Rollen-Archetyp (außen-zugewandt): Orchestrator speziell für Agenten-Flotten als „digitale Mitarbeiter"; führt Agenten wie ein Team: briefen, beobachten, Ergebnisse abnehmen. | [Modul 9](./09-rollen-archetypen.md) |
| **Connector (claude.ai)** | Auf dem claude.ai-Account verbundene MCP-Integration (z.B. Slack, Linear), die Cloud-Routines als Tool-Zugriff nutzen; getrennt von lokal per `claude mcp add` registrierten Servern. | [Modul 8](./08-agenten-skalierung.md) |
| **Context Engineering** | Disziplin, dem Agenten zur richtigen Zeit die richtigen Informationen im Context-Window bereitzustellen: welche Dateien, welche Regeln, welche Beispiele. Umfasst u.a. die richtige „Altitude" des System-Prompts, Tool-Minimalismus und JIT-Retrieval. | [Modul 10](./10-kontext-engineering.md) |
| **Context Rot** | Leistungsabfall eines Agenten, wenn sein Context-Window sich füllt: Er „vergisst" frühe Anweisungen und macht eher Fehler, je voller das Fenster ist (*„performance degrades as it fills"*). | [Modul 7](./07-agenten-grundlagen.md) · [Modul 10](./10-kontext-engineering.md) |
| **Context-Window** | Arbeitsgedächtnis eines LLM-Agenten: alle Nachrichten, Dateien und Ausgaben, die gerade „drin" sind; begrenzt, füllt sich schnell. | [Modul 7](./07-agenten-grundlagen.md) · [The map (EN)](../../tracks/04-the-map/01-model-context-agent.md) |
| **Custom Subagent (`.claude/agents/`)** | Als Markdown-Datei definierter Subagent mit eigenem System-Prompt (Datei-Body), eigenen Tool-Rechten (`tools`) und Modellwahl (`model`), im Repo geteilt (`.claude/agents/`) oder persönlich (`~/.claude/agents/`). | [Modul 7](./07-agenten-grundlagen.md) |
| **/deep-research** | Mitgelieferter (bundled) Workflow: fächert Web-Recherche auf mehrere Subagents auf, prüft die Quellen gegeneinander und liefert einen zitierten Report. | [Modul 8](./08-agenten-skalierung.md) |
| **Delegation-Gap** | Die Lücke zwischen dem, was ein Mensch einem Agenten übergeben möchte, und dem, was der Agent zuverlässig eigenständig erledigen kann; zu frühe Delegation ohne Verifikation erzeugt schwer findbare Fehler. | [Modul 7](./07-agenten-grundlagen.md) |
| **Dynamic Workflow / Dynamische Workflows** | JavaScript-Script, das Claude schreibt und das viele Subagents lokal orchestriert (bis 16 gleichzeitig, max. 1.000 pro Run, Stand 2026-07-06); Zwischenergebnisse bleiben im Script statt im Context-Window. | [Modul 8](./08-agenten-skalierung.md) |
| **Editor** | Rollen-Archetyp (außen-zugewandt): entscheidet, welche der vielen Prototypen weiterleben; kuratiert statt erzeugt, denn wenn Bauen billig wird, bleibt Markt-Aufmerksamkeit knapp und jemand muss Nein sagen. | [Modul 9](./09-rollen-archetypen.md) |
| **Eval** | Kuratierter Testfall-Satz, an dem Modellverhalten über Zeit gemessen wird; lebt meist nur wenige Modellgenerationen, bevor er saturiert (das Modell besteht ihn durchgehend) und ersetzt wird. Nicht zu verwechseln mit dem `/goal`-**Evaluator** (Modul 8), der einen einzelnen laufenden Task bewertet. | [Modul 10](./10-kontext-engineering.md) |
| **Evangelist** | Rollen-Archetyp (außen-zugewandt): bringt den Markt zur Sicht der Builder (Content, Conversation, Community); die Gegenrichtung zum Scout, Signal geht nach draußen statt herein. | [Modul 9](./09-rollen-archetypen.md) |
| **Evidenz** | Belegbare Ausgabe statt Behauptung: Test-Output, `git diff`/`git status`, Screenshot, Pipeline-Link. Kurzformel: „Verlange Evidenz, vertraue nicht." | [Modul 7](./07-agenten-grundlagen.md) · [Verification ladder (EN)](../../tracks/05-verify-and-loop/01-verification-ladder.md) |
| **Fable (Alias `fable`)** | Anthropic-Modell für lange, schwierige Aufgaben; der Alias `fable` zeigt ab Claude Code v2.1.257 auf Fable 5.1. Kein Default, muss explizit per `/model` gewählt werden. (Stand 2026-09-13, Quelle: https://code.claude.com/docs/en/model-config) | [Modul 7](./07-agenten-grundlagen.md) |
| **Fan-out** | Muster: Agent generiert eine Task-Liste, ein Skript loopt über die Liste (je ein `claude -p` bzw. `codex exec` pro Eintrag) und verarbeitet so viele Dateien. | [Modul 8](./08-agenten-skalierung.md) |
| **Fork-Subagent (`/subtask`)** | Subagent, der den vollen bisherigen Gesprächskontext erbt, statt frisch zu starten; nur sein Endergebnis kommt zurück, der Haupt-Context bleibt sauber. Gestartet mit `/subtask`; `/fork` kopiert dagegen die Session in eine neue Background-Session (Stand 2026-09-13). Nicht zu verwechseln mit Fork (Repo). | [Modul 7](./07-agenten-grundlagen.md) |
| **/goal** | Claude-Code-Befehl, der eine Completion-Condition setzt; ein Evaluator prüft nach jedem Turn und urteilt *not met*, *met* oder *impossible*. (Stand 2026-09-13, verifizieren gegen `code.claude.com/docs/en/goal`) | [Modul 8](./08-agenten-skalierung.md) |
| **Grower** | Rollen-Archetyp: verbessert ein Produkt anhand echter Nutzung: Löst es ein Problem, für das Menschen es wieder verwenden wollen? | [Modul 9](./09-rollen-archetypen.md) |
| **Headless-Mode** | Agent läuft ohne interaktive Session: `claude -p "…"` gibt einen Auftrag, der Agent erledigt ihn und beendet sich. | [Modul 8](./08-agenten-skalierung.md) |
| **Inference** | Eines der drei Anonymitäts-Risiken: Lässt sich ein Attribut einer Person mit hoher Sicherheit ableiten, auch ohne sie zu identifizieren? Trägt z.B., wenn alle Mitglieder einer kleinen Gruppe dasselbe Merkmal haben. | [Modul 11](./11-kundendaten-testdaten.md) |
| **jagged intelligence** | Begriff für das ungleichmäßige Fähigkeitsprofil von LLMs: in manchen Bereichen übermenschlich, in anderen, v.a. bei seltenen APIs oder unbekannten Pfaden, überraschend fehlerhaft. | [Modul 7](./07-agenten-grundlagen.md) |
| **Leak-Guard** | Check, der Alarm schlägt, wenn ein echter Wert aus der Originaldatei doch in die synthetische Ausgabe gelangt ist; die mechanische Gegenprobe zur Disziplin. | [Modul 11](./11-kundendaten-testdaten.md) |
| **Linkability** | Eines der drei Anonymitäts-Risiken: Lassen sich zwei Datensätze über gemeinsame Merkmale verknüpfen, sodass zusammen wieder eine Person entsteht? | [Modul 11](./11-kundendaten-testdaten.md) |
| **llms.txt / „Build for agents"** | Konvention: eine maschinenlesbare Datei `llms.txt` im Root einer Website, die Agenten erklärt, wie sie die Site sinnvoll nutzen sollen; Analogon zu `robots.txt`, aber für LLM-Clients. | [Modul 10](./10-kontext-engineering.md) |
| **Long-horizon Memory** | Gedächtnis über Session-Grenzen hinaus: Agenten schreiben Erkenntnisse in Dateien (z.B. `MEMORY.md`), die spätere Sessions wieder einlesen; schließt die Lücke des flüchtigen Context-Windows. | [Modul 10](./10-kontext-engineering.md) |
| **`/loop` (self-paced)** | Claude-Code-Befehl, der den Agenten wiederkehrend re-triggert; ohne Intervall wählt Claude die Verzögerung selbst (1–60 min) und kann den Loop selbst beenden, wenn die Arbeit fertig ist. (Stand 06/2026, verifizieren gegen `code.claude.com/docs/en/scheduled-tasks`) | [Modul 8](./08-agenten-skalierung.md) |
| **loop.md / Maintenance-Modus** | Die Datei `.claude/loop.md`: Ihr Inhalt ist der Prompt, den ein `/loop` ohne Argument (Maintenance-Modus) jede Iteration ausführt; bestimmt, was der Wartungslauf tut und wann er sich beendet. | [Modul 8](./08-agenten-skalierung.md) |
| **Maintainer (Rollen-Archetyp)** | Rollen-Archetyp: hält ein bestehendes System zuverlässig: Fehler beheben, aktualisieren und den Betrieb bei mehr Nutzung anpassen. | [Modul 9](./09-rollen-archetypen.md) |
| **MCP (Model Context Protocol)** | Offener Standard, der einem Agenten zusätzliche externe Tools und Datenquellen über sogenannte MCP-Server bereitstellt. Claude Code lädt MCP-Tools ab v2.1.232 per Tool Search erst bei Bedarf (Quelle: https://code.claude.com/docs/en/mcp). | [Modul 7](./07-agenten-grundlagen.md) |
| **MCP-Scope (local/user/project)** | Sichtbarkeitsebene einer MCP-Server-Konfiguration: `local` = nur du in diesem Projekt, `user` = nur du in allen Projekten, `project` = alle Teammitglieder via `.mcp.json`. | [Modul 7](./07-agenten-grundlagen.md) |
| **.mcp.json** | Eingecheckte Team-Konfigurationsdatei im Repo-Root, die MCP-Server für alle Projektmitglieder definiert; Scope `project`, ergänzt user- und local-Konfiguration. | [Modul 7](./07-agenten-grundlagen.md) |
| **Monitor-Tool** | Claude-Code-Tool, das stdout eines Hintergrundprozesses als Notification-Stream liefert; token-effizienter als wiederholtes Polling. | [Modul 8](./08-agenten-skalierung.md) |
| **OpenClaw** | Open-Source-Agent-Framework mit direktem Shell- und Dateizugriff by design; als reiner Chat-Assistent nur mit gesperrten Tool-Zugriffen und Sandbox sinnvoll. | [Always-on assistants (EN)](../../tracks/08-advanced/05-always-on-assistants-guardrails.md) |
| **Orchestrator (Rollen-Archetyp)** | Rollen-Archetyp (außen-zugewandt): koordiniert Rollen-Bündel und Arbeitsströme über Teams hinweg. Gemeint ist die **menschliche Rolle**, nicht der technische Orchestrator-Agent (übergeordneter Agent, der Subagents startet, siehe **Subagent**). | [Modul 9](./09-rollen-archetypen.md) |
| **Permission-Modi** | Abstufungen der Tool-Freigabe in Claude Code: Manual (früher `default`, interaktive Bestätigung), `acceptEdits` (Datei-Edits auto-ok, Befehle weiter mit Nachfrage), `plan` (nur lesen/planen), `auto` (Classifier-gestützt, blockt nur Riskantes; auf Pro/Max/Team Startmodus ab v2.1.228 (macOS/Linux/WSL) bzw. v2.1.233 (Windows nativ)), `dontAsk` (keine Rückfrage, **ohne** Safety-Classifier), `bypassPermissions` (alle Checks aus, **nur in Container/VM, niemals auf Maschinen mit echten Daten oder Keys**). | **Plan Mode** | Agent recherchiert und plant, ohne Änderungen vorzunehmen; `Ctrl+G` öffnet den Plan zum Editieren. Sinnvoll bei größeren Änderungen, Overhead bei Ein-Satz-Diffs. | [Modul 7](./07-agenten-grundlagen.md) |
| **Plugins** | Verpackung für geteilte Bausteine: bündeln Skills, Hooks, Subagent-Definitionen und MCP-Server-Definitionen zu **einer** installierbaren Einheit, verteilt über ein Marketplace-Repo. | [Modul 8](./08-agenten-skalierung.md) |
| **Prompt-Cache (TTL)** | Anthropic-Mechanismus: Ein vorab berechneter Kontext-Prefix wird standardmäßig 5 Minuten gehalten; trifft ein Loop-Tick innerhalb dieser Zeit, zahlt er nur den günstigeren Cache-Read. (Stand 2026-06-29, Quelle: `platform.claude.com/docs/en/build-with-claude/prompt-caching`) | [Modul 8](./08-agenten-skalierung.md) |
| **Prototyper** | Rollen-Archetyp: baut eine kleine erste Version, damit andere eine Idee ausprobieren und beurteilen können. | [Modul 9](./09-rollen-archetypen.md) |

| **Risk Steward** | Rollen-Archetyp (außen-zugewandt): prüft früh mögliche Schäden, notwendige Freigaben und Schutzmaßnahmen. | [Modul 9](./09-rollen-archetypen.md) |
| **Routine-Trigger** | Startauslöser einer Cloud-Routine: Schedule (Intervall min. 1 Stunde), API-Endpoint (mit Bearer-Token) oder GitHub-Event (PR/Release); GitHub-Trigger lassen sich seit Claude Code v2.1.225 auch per CLI anlegen (Quelle: https://code.claude.com/docs/en/routines). | [Modul 8](./08-agenten-skalierung.md) |
| **Sandboxing / `/sandbox`** | Permission-Mechanismus, der Agent-Aktionen per OS-Level-Isolation einschränkt (Filesystem und Netzwerk restringiert); die härteste Leitplanke neben Permission-Allowlist und Auto Mode. | [Modul 8](./08-agenten-skalierung.md) |

| **System Prompt** | Die vom Tool-Anbieter (z.B. Anthropic für Claude Code) mitgelieferte Grund-Instruktion, die bei jedem Turn mitläuft; zu unterscheiden von der `CLAUDE.md`, die du selbst pflegst. Beide kosten Context bei jedem Aufruf. | [Modul 10](./10-kontext-engineering.md) |

| **Tool Search** | Mechanismus in Claude Code (Default ab v2.1.232), der MCP-Tools erst bei Bedarf lädt, statt alle Tool-Definitionen dauerhaft ins Context-Window zu legen. (Stand 2026-09-13, Quelle: https://code.claude.com/docs/en/mcp) | [Modul 7](./07-agenten-grundlagen.md) |
| **ultracode** | Trigger-Keyword im Prompt, das einen einzelnen Dynamic-Workflow-Run startet; als `/effort ultracode` ein Session-Modus (xhigh-Effort plus automatische Workflows), tokenintensiv, gezielt einsetzen. | [Modul 8](./08-agenten-skalierung.md) |

| **Vibe Engineering** | Diszipliniertes Arbeiten mit Coding-Agenten: planen, gegenprüfen, testen. Der Agent erledigt die Arbeit, aber die **Accountability bleibt beim Menschen** (Begriff von Simon Willison). | [Modul 7](./07-agenten-grundlagen.md) |
